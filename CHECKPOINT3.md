# Checkpoint 3 (RLVR and combined reward) — Sheldon Cooper persona on Qwen2.5-3B-Instruct

**Character:** Dr. Sheldon Cooper. **Base model:** `Qwen/Qwen2.5-3B-Instruct`. **Starting point:** the checkpoint-2 RLAIF model `grpo-v2`.
**STEM task for this stage:** competition math, MATH-500 (levels 3–5 as the headline), with GSM8K and AIME 2024/25/26 reported alongside.
**Submitted models:** `RLVR-math-v2-fullft` (best persona-plus-math model, run 3) and `Combined-v1` (run 4, combined RLAIF + RLVR reward).

**Headline.** Four RL runs on top of `grpo-v2`. RLVR with a verifiable math reward recovered nearly all of the competition-math ability the
persona SFT stage had removed: MATH-500 avg@4 29.6 → 65.1 and levels 3–5 21.0 → 56.9 (base model 66.6 / 59.0), GSM8K 63.6 → 83.0
(base 86.1), while the persona, measured with the checkpoint-2 judge and monitors, stayed intact (judge win rate vs the seed 0.50–0.55).
The LoRA run plateaued at step ~125 when half the prompt groups had become all-correct; a staged re-labelling of the difficulty schedule
with a 5× larger prompt pool fixed the dead-group problem (47% → 6–9%) but not the plateau, and a full-parameter fine-tune at 2e-6 did
(+1.6 avg@4, +1.7 on levels 3–5, monotone over checkpoints). The final combined-reward run kept math unchanged and removed every persona
defect the checkpoint-2 rules penalise (rule penalty 0.87 → 0.15, template openers 64% → 4%, truncation 18% → 1%) but did so by becoming
terse (90 words vs gold 262, cast names 8% vs 70%): the persona reward's only positive term is relative to sibling completions, so the
policy descended the penalty landscape instead. Section 6 dissects this with the per-term reward trajectory.

## 2. Task choice

We surveyed what Qwen2.5-3B-Instruct scores and what RLVR papers achieve at 3B before choosing the task. The base model scores 62–66 on
MATH-500 and 0–3 on AIME pass@1; published RLVR runs at 3B end at 63–68 and 2–3 AIME problems of 30, with most of the gain in the first
60–150 steps, and pass@256 does not move (RL sharpens what the model can already sample). AIME as the primary task was rejected: one
problem is 3.3 points and its training sets put a 3B model in the all-wrong regime. MATH-500 levels 3–5 were chosen as the decision
metric, AIME kept as avg@16 for the record. Our own baseline then showed the real headroom: the persona stages had cost the model 34
points on MATH-500 (68.0 → 34.0 greedy) and 22 on GSM8K, and the checkpoint-1 touch-up model was equally low, so the loss dates to SFT.

## 3. Method

**Recipe** (design decisions made before any run; rationale in `rlvr/PLAN.md`):
- **Loss: CISPO** (MiniMax-M1): token-level importance ratio, clipped from above only at ε_max = 5, stop-gradient on the ratio, REINFORCE
  form, no KL term. Chosen over GRPO/DAPO/GSPO on the ScaleRL evidence. TRL's implementation uses `epsilon_high` as the absolute cap, so
  the default 0.2 would have silently capped ratios at 0.2; set to 5.
- **Aggregation: the DAPO-paper formula** (token mean within each prompt's group, then mean over prompts; ScaleRL's "prompt average").
  TRL only offers a batch-wide token mean, so the trainer reweights each completion's advantage by N / (T_g · P_live), which is exact
  because the CISPO policy term is linear in the advantage.
- **Advantage: group mean baseline with group-level std** — a deliberate choice against ScaleRL's batch-level std, because with binary
  rewards it up-weights the extreme (nearly all-right or all-wrong) groups.
- **Truncations and zero-variance groups masked**: a truncated completion returns no reward, so it leaves the group mean/std (TRL's
  nan-aware baseline) and, with `mask_truncated_completions`, the loss and its denominator; groups whose rewards are all equal are
  removed from the loss and denominators by the trainer. A group of 16 with one truncation behaves as a group of 15.
- **Reward**: 1 if the last `\boxed{}` answer matches the reference (exact fast path, else `math-verify` symbolic equivalence), else 0;
  no format reward (the seed boxes 99.8% of answers). DAPO soft overlong penalty (cache 512 tokens) on terminated completions, kept after
  its pilot.
- **Batch and rollouts**: 16 prompts × 16 completions per step, T 1.0, top-p 1.0, no repetition penalty (the checkpoint-2 run's 1.05 had
  put vLLM and the trainer out of agreement: logged importance ratio 0.03), 2,048-token cap, one update per batch (on-policy), vLLM
  token-level truncated importance-sampling correction on.
- **Precision**: fp32 master weights with bf16 autocast (a 1e-6 update is below bf16 resolution) and an fp32 LM head computed outside
  autocast on the trainer (both arms; TRL's own flag is undone by autocast and crashes on PEFT models). bf16 vLLM sampler: the smoke test
  measured the per-token trainer-vs-sampler log-prob gap at 0.017 (fp32 sampler: 0.008) with the importance ratio at 1.000.
- **Schedule**: warm-up / stable / linear decay (WSD) to 10% of peak over the last 20%.
- **Difficulty schedule**: every training prompt is labelled with the current model's pass rate over 8 rollouts (12k × 8 rollouts take
  ~3 min on three H200s). Run 1 used a static mixture over easy / medium / hard buckets drifting harder over the run; runs 2–4 sample by
  p(1−p) inside [1/8, 7/8] plus a 10% slice of never-solved prompts, with per-source caps (MATH-12k ≥ 30%, DeepMath ≤ 30%, DAPO ≤ 20%,
  DeepScaleR ≤ 20%), re-labelled with the current model at every stage boundary. No dynamic sampling within a run.
- **Infrastructure**: TRL 1.13 `GRPOTrainer` subclass; 3× H200 (H100s were unavailable): one GPU serves vLLM (full fine-tune runs) or
  evaluates (LoRA runs), two GPUs train under DDP. Pod fixes needed: CUDA-12.9 builds on a 12.8 driver, `ninja` for vLLM, `NCCL_NVLS_ENABLE=0`
  for the trainer-to-vLLM weight sync. A pre-run adversarial code review (110 agents) found nine defects that would have cost pod time.

**Pilots (20 steps each, identical prompts; decision rules fixed in advance).** LoRA r32 + AdamW 2e-5 vs full fine-tune + AdamW 1e-6:
LoRA 25.7 vs full FT 22.8 on MATH-500 L3–5 avg@4 (seed 21.0), so LoRA won under the "full FT must lead by > 3 points" rule and the
planned Muon / Muon^p optimizer pilots were skipped. Length penalty on vs off: truncations 3.6% → 3.0% with L3–5 flat (+0.5), so the
penalty stayed on (both differences inside the ±1.5-point noise band).

Each run starts from the previous row's model (run 3 from run 1's final checkpoint, not run 2's). Greedy MATH-500 for the final models:
run 1 65.0, run 3 65.4, run 4 65.2, base 68.0.

**Run 1 — LoRA RLVR, 200 steps (2 h 13 min on two H200s).** MATH-500 L3–5 avg@4 by checkpoint: 27.3, 35.4, 43.5, 49.6, 52.9, 52.3,
55.2, 55.2 at steps 25–200. Training reward 0.48 → 0.69, completions 357 → 541 tokens. The plateau from step ~125 coincided with the
zero-variance fraction reaching ~0.5: the dead groups were **all-correct** (2% → 40% of the batch by step 100) while all-wrong stayed at
~10%. The schedule's labels came from the seed at step 0 and never moved while the policy went from 43% to 73% accuracy on the same mix.

**Run 2 — staged re-labelling from run 1's final model.** Pool expanded to 64.7k prompts; every 50 steps the whole pool is re-labelled
with the current model and the next block sampled by p(1−p). Dead groups fell to 6–9% and the training reward sat in the informative
0.4–0.5 band, but two stages were flat (L3–5 55.0 / 55.3). The re-labelling itself proved it: on the 31,401 prompts trained in stage 1 the
pass rate went 0.447 → 0.449 (37% up, 39% down: sampling noise). A plateau of the recipe, not of the data; stopped before its third stage.

**Run 3 — full fine-tune at 2e-6, 100 steps, same schedule.** L3–5 by checkpoint 55.2, 55.4, 56.0, 56.9 (monotone, largest step in
the LR decay), avg@4 63.6 → 65.1, level 4 now equal to base (60.9 vs 60.5), GSM8K 83.0. The gain is at the edge of the noise band but
consistent across four checkpoints and the greedy number. Full-parameter updates moved where the rank-32 adapter did not. Gradient
norm ~0.5 (LoRA: 0.1), relative parameter drift 6.8e-4 over the run.

**Run 4 — combined reward, 80 steps.** Each step: 8 math prompts (verifier, band schedule) + 8 persona prompts (checkpoint-2 RL set,
reward = gate × (2 × pairwise judge win rate + form) − 17 rules − false-claim − batch tax; GPT-5.6 Luna, both orders), 16 completions each,
2,048-token cap for both so that the rules' length terms, not the cap, discipline verbosity; group-level normalisation keeps the two reward
scales apart. Judge cost $25, no errors. Math unchanged. Persona: see section 6.

## 6. Persona

Same protocol as checkpoint 2: 502 held-out prompts (+ 40 OOD, + 60 short prompts), greedy, 400 tokens; deterministic monitors from
`rlaif/audit/quant/compare.py`; the calibrated Luna judge head to head against `grpo-v2` on 200 prompts in both presentation orders
(`results/rlvr/persona_*.md`, `results/rlvr/judge_h2h_*.json`). Persona leakage into math answers = share of MATH-500 answers naming
Sheldon or the cast.

| rule penalty (17 terms) | 0.870 | 1.023 | 1.197 | 0.154 | 0.653 |

**Runs 1 and 3 (math-only reward).** The persona survived RLVR on substance: more cast names and Bazinga than the seed, fewer announced
jokes and template openers, fewer canon errors, less leakage into math; the judge rates run 1 slightly above the seed and run 3 level with
it. The one side effect is verbosity: RLVR taught longer answers, so replies to chat prompts hit the 400-token cap twice (run 1) to
two-and-a-half times (run 3) as often, and short prompts get longer replies. That is what pushes the rule penalty up (its length and
truncation terms) and what the combined stage was meant to fix.

**Run 4 (combined reward).** Every defect is gone and the leakage into math is at the base model's level, but the persona's substance
thinned with the length: 90 words, cast in 8% of replies, no Bazinga; the judge scores a tie, winning the defect-shaped items (template
+0.86, answer-first +0.73, humour/canon +0.73, register +0.58) and losing "voice" (−0.34). Per-term trajectory of the training reward:

| term (20-step means) | 1–20 | 21–40 | 41–60 | 61–80 |
|---|---|---|---|---|
| persona reward R | −0.60 | 0.22 | 0.53 | 0.71 |
| pairwise win rate P | 0.48 | 0.49 | 0.50 | 0.50 |
| gate G | 0.56 | 0.60 | 0.60 | 0.63 |
| form bonus F | 0.26 | 0.40 | 0.47 | 0.48 |
| rule penalty | 0.90 | 0.38 | 0.19 | 0.13 |
| batch tax | 0.23 | 0.12 | 0.06 | 0.04 |
| mean words / any cast name / Bazinga | 264 / 51% / 9% | 168 / 36% / 2% | 105 / 22% / 1% | 85 / 17% / 1% |

The whole reward gain is the rule penalty and the tax going to zero; P never moved. With group-normalised advantages only within-group
differences matter, and P is zero-sum within a group by construction (mean 0.5 whatever the group looks like) with a noisy sign (56%
order consistency), so it can re-order siblings but cannot say "this whole group has drifted out of character". The rules and the tax
differ between siblings consistently every step (the shorter sibling that names nobody and opens plainly always has the smaller penalty), and
a consistent signal beats a noisy zero-sum one. The rules were written against the checkpoint-2 failure audit and are almost all negative
space; the batch tax even penalises the persona's own signature phrases; the judge rubric is mostly negative space too, with `voice` the
only substance item. Checkpoint 2 did not show this because its LoRA barely moved the policy (rule penalty 1.00 → 0.87 in 109 steps); a
full-parameter policy at 2e-6 found the basin in ~60 steps. The training monitors suggest run 4's step-20 checkpoint (233 words, cast in
45% of replies, template openers already down to 18%) sits between the two; it was not evaluated held-out.

What a user sees (`persona_eval/gens/`): to "good morning!" run 3 writes 86 words about the roommate agreement and Rayleigh scattering and
run 4 writes "Good morning."; to "What do you do for fun?" run 3 gives 114 words on vintage games and Star Trek, run 4 gives one sentence
about Halo with Leonard and teaching Penny rock-paper-scissors-lizard-Spock; on a long advice prompt run 3 hits the cap mid-list while run 4
gives 112 words of compact advice with one barb. Run 3 is Sheldon who will not stop talking; run 4 answers the question well and only
occasionally reminds you who he is.

**Why math and persona barely traded off in runs 1–3.** The math reward never sees persona text and the persona reward never sees
math prompts, and RL at this scale sharpens the existing distribution rather than replacing it: the persona was already in every sampled
answer, so RLVR could reallocate probability toward correct chains of reasoning without leaving the persona's support. The only coupling was
length: longer chains of thought on math carried over into longer chat replies.

## 8. What a next run would change

1. A positive, non-sibling-relative persona term: judge each completion against the gold reply for its prompt, or an absolute 0–10 voice
   rubric, or a reference-log-prob / KL anchor to the seed on persona rows only.
2. A floor on reply length relative to the prompt kind; the rule penalties capped (total ≤ 0.5) or reduced to a gate on egregious defects;
   no batch tax on canonical catchphrases.
3. Evaluate run 4's step-20 checkpoint held-out (the fp32 checkpoint is preserved) as the likely balance between defect removal and persona.
4. On the math side, the remaining gap to base is level 5 and AIME; a longer full-fine-tune run with staged re-labelling is the only lever
   that moved, at roughly 60 s per step on this hardware.
