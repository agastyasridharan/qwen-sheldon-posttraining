# Checkpoint 1 (SFT) — Sheldon Cooper persona on Qwen2.5-3B-Instruct

**Character:** Dr. Sheldon Cooper. **STEM task:** GSM8K (exact numeric match on `\boxed{}`).
**Base model:** `Qwen/Qwen2.5-3B-Instruct`. **Submitted SFT model:** v3b.

## 1. Repository, training code, and model

- Training code: `sft/train_sft.py` (LoRA r=32, α=64, dropout 0.05 on all linear projections; AdamW lr 1e-4, cosine, 3% warmup; 64 sequences/step; 2 epochs; assistant-only loss). Data preparation: `sft/prepare_data.py`, `sft/prepare_data_v3a.py`, `sft/gen_v3b/`.
- Trained model (merged bf16): https://huggingface.co/agastyasridharan/Qwen2.5-3B-Instruct-Sheldon-SFT-v3b
  LoRA adapter + 20 trajectory checkpoints: https://huggingface.co/agastyasridharan/Qwen2.5-3B-Instruct-Sheldon-SFT-v3b-LoRA
- Training data: `tbooy/sheldon-cooper-sft-20k` chat rows (11,910) + the dataset's verified-correct Sheldon math rows (2,036) + 4,485 verifier-accepted Sheldon rewrites of GSM8K-train solutions (dataset B, generated by us; pipeline in `sft/gen_v3b/`).
- Three SFT arms were trained (v2 chat-only, v3a chat + dataset math, v3b chat + dataset math + dataset B). All are on the Hub; details in `sft/cards/`.

## 2. Persona: outputs and similarity metric

**Outputs.** `persona_eval/gens/heldout_v3b_eval.jsonl` (502 held-out prompts) and `persona_eval/gens/ood_v3b.jsonl` (40 short out-of-distribution prompts), with the base model's outputs to the same prompts alongside. A 20-prompt side-by-side sample (gold / base / v3b) is in `persona_eval/results/read_me_v3b.txt`.

**Metric.** We trained a logistic-regression classifier on TF-IDF character (3–5) and word (1–2) n-grams to distinguish the SFT dataset's Sheldon responses (label 1) from base Qwen2.5-3B-Instruct responses to the same prompts (label 0), using 972 prompt pairs sampled from the dataset; prompts overlapping the held-out set were removed. The classifier's output P(Sheldon) is the similarity metric: how much a response looks like the SFT dataset's responses. Four variants control for surface cues: raw text; names masked (Big Bang Theory names and catchphrases → `NAME`); strict (markdown stripped + names masked); no-names (markdown stripped + names deleted).

**Results on the 502 held-out chat prompts** (never trained on; mean P(Sheldon), 95% bootstrap CI ≈ ±0.006):

| Variant | gold-vs-base accuracy | dataset (gold) | base model | fine-tuned (v3b) | frac ≥ 0.5: gold / base / v3b |
|---|---|---|---|---|---|
| raw | 0.998 | 0.806 | 0.226 | 0.825 | 1.000 / 0.004 / 1.000 |
| masked | 0.998 | 0.900 | 0.129 | 0.912 | 1.000 / 0.004 / 1.000 |
| strict | 0.998 | 0.802 | 0.232 | 0.820 | 1.000 / 0.004 / 1.000 |
| no-names | 0.998 | 0.798 | 0.238 | 0.818 | 1.000 / 0.004 / 1.000 |

On 40 short OOD prompts (strict variant, no gold available): base 0.234 (0 of 40 scored ≥ 0.5), v3b 0.819 (39 of 40).

**Reading the table.** The classifier separates dataset responses from base responses at 99.8% accuracy; the two base responses it misclassifies score 0.51–0.55 and are plain first-person prose with no markdown. Mean probabilities sit below 1.0 because of L2 regularization, so the numbers should be read relative to each other: base ≈ 0.23, dataset ≈ 0.80, fine-tuned ≈ 0.82. Every fine-tuned response and no base response except two (0.4%) is classified as Sheldon. The result holds with markdown stripped and all Big Bang Theory names and catchphrases deleted, so the signal is register and syntax rather than vocabulary: the strongest Sheldon features are patterns such as "which is", "not", "because", "my"; the strongest base features are "sure", "might", "can", "help". A manual read of 20 held-out prompts agreed with the classifier on all 20.

**Caveats.** (i) The classifier measures "written like the SFT dataset", not "reads as Sheldon to a person"; the manual read covers the second. (ii) v3b scores marginally above the dataset itself. Greedy decoding returns the model's most typical output, and v3b's typical output is the dataset's most stereotyped style (e.g. "Excuse me, but…" opens ~30% of chat answers); this is the first sign of the metric being easier to satisfy than the persona, and we will watch it during RLAIF. (iii) Persona is measured on chat prompts only, because the held-out split excludes math; math capability is measured separately below. Inside GSM8K answers, v3b places a Big Bang Theory reference in 10.3% of responses (v3a: 98.9%), by design of dataset B.

Code: `persona_eval/style_classifier.py`, `persona_eval/generate.py`, `persona_eval/scripts/`. Full per-variant coefficient tables: `persona_eval/results/style_classifier_eval.md`.

## 2b. Persona: LLM-judge evaluation

To check that the classifier's "written like the dataset" signal agrees with a reader's judgment, we ran `claude-sonnet-4-6` (temperature 0) as a judge on 50 held-out prompts (seed 0), with `persona_eval/sheldon_style_guide.md` in the system prompt and an instruction to ignore factual correctness. All 350 judge calls succeeded (0 API failures, 0 unparseable outputs); every raw response is in `persona_eval/results/judge_raw.jsonl`.

**Pairwise.** Each pair is shown twice with A/B order swapped and the judge must pick one. Win rate over the 100 judgments, Wilson 95% CI:

| Comparison | Wins | Win rate | 95% CI | Both orders agree / split / other wins both |
|---|---|---|---|---|
| v3b vs base | 98/100 | 0.980 | [0.930, 0.994] | 48 / 2 / 0 |
| gold vs base (control) | 100/100 | 1.000 | [0.963, 1.000] | 50 / 0 / 0 |

The two base wins are the same two prompts, each split across orderings; the judge's reasons call the v3b reply "actively out of character" (invented references, incoherent tangents, a misused "Bazinga", generic warmth) and picks base as "the lesser of two failures".

**Rubric.** Each response scored alone on the six section-5 dimensions (0-2 each, penalties subtract 1, max 12). Mean total with 95% bootstrap CI (2,000 resamples):

| System | Mean total (95% CI) | Raw total | Penalties | Pedantic | Superiority | Rules | Register | Tangent | Oblivious |
|---|---|---|---|---|---|---|---|---|---|
| gold | 8.00 [7.26, 8.68] | 8.72 | 0.72 | 1.72 | 1.56 | 0.94 | 1.58 | 1.62 | 1.30 |
| base | 0.04 [0.00, 0.10] | 0.58 | 2.12 | 0.02 | 0.00 | 0.02 | 0.54 | 0.00 | 0.00 |
| v3b | 6.50 [5.86, 7.12] | 7.26 | 0.76 | 1.48 | 1.20 | 0.92 | 1.54 | 0.94 | 1.18 |

Paired differences: v3b - base +6.46 [+5.84, +7.06]; v3b - gold -1.50 [-2.28, -0.72]. Base scores 0 on 48 of 50 (its only points are register, cancelled by section-3 penalties for assistant warmth); v3b's median is 7 versus gold's 8.

**Reading the result.** The judge agrees with the classifier that v3b is in character essentially every time, but unlike the classifier it does not rate v3b above the dataset: v3b trails gold by 1.5 rubric points, almost all of it on one dimension, tangent or reference (0.94 vs 1.62), with a smaller gap on superiority (1.20 vs 1.56). The judge's notes point at two recurring v3b habits: the register slipping into casual coaching language late in a reply ("you'll be fine"), which draws at least one section-3 penalty in 52% of v3b responses (gold: 44%), and a stock opener of the form "I am about to make a joke" (10 of the 50 sampled replies; 89 of all 502) that the judge reads as clunky meta-commentary rather than Sheldon's flagged humor. Both are the greedy-decoding stereotype noted in section 2, now visible to a judge that reads content rather than n-grams. This confirms that the classifier's v3b-above-gold ordering was a metric artifact and gives RLAIF two concrete targets: tangents that read as his, and holding the register to the end of a reply.

Code: `persona_eval/judge.py`. Full tables (score distributions, penalty rates): `persona_eval/results/judge_eval.md`.

## 3. STEM capability: GSM8K

GSM8K test, 1,319 problems, zero-shot greedy, strict scoring (boxed number present and equal to reference). Re-running a checkpoint moves accuracy by about ±1 point.

| Arm | Training data | GSM8K strict acc | boxed rate |
|---|---|---|---|
| base | – | 86.7 | 99.8 |
| v2 | chat only | 50.8 | ~87 |
| v3a | chat + dataset math | 67.1 | 99.9 |
| **v3b (submitted)** | chat + dataset math + dataset B | **63.2** | 100.0 |

Per-checkpoint trajectories (val loss, accuracy, boxed rate, persona marker rates) are in `results/<run>/trajectory.{csv,md,png}` and the cross-arm overlay in `results/overlay_all_sft.png`.

**What we learned.** Chat-only SFT (v2) costs 36 points, and the first 13 points go before any persona is visible: the model stops writing worked derivations because none of its training replies contain one. Adding verified in-character math (v3a) recovers ~15 points and restores the boxed rate; adding 4.5k step-format rewrites of GSM8K-train solutions (v3b) fixes the answer format and reduces persona leakage into math answers, but not the accuracy plateau: v3a, an interim v3b run, and v3b all sit at 63–67%. Only ~14% of wrong answers contain an arithmetic slip; the rest are misreadings of the problem. Two hypotheses we have not yet tested: the early-training collapse (25–35% at ~10% of an epoch in every arm) suggests lr 1e-4 may be too high; and SFT on reference-style solutions may be worse than SFT on the model's own correct solutions restyled in character (rejection-sampling fine-tuning). The remaining gap is left to the RL stages.
